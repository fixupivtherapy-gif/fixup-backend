# 08 — i18n

## Strategy #decision

- **Library:** `next-intl` v3.x
- **Default locale:** `es` (Spanish, no region specifier — covers es-MX and es-US speakers)
- **Locales:** `['es', 'en']`
- **Locale prefix:** `always` (every URL is `/es/...` or `/en/...`)
- **Default redirect:** root `/` → `/es`

## Config files

- `web/i18n/routing.ts` — defines locales, default, prefix mode
- `web/i18n/request.ts` — loads `messages/{locale}.json` per request
- `web/middleware.ts` — wires next-intl middleware
- `web/next.config.mjs` — `createNextIntlPlugin('./i18n/request.ts')`

## Message catalog structure

`web/messages/es.json` and `web/messages/en.json` are mirror catalogs.
Top-level namespaces:

| Namespace      | Used for                                            |
| -------------- | --------------------------------------------------- |
| `brand`        | Wordmark, tagline, subline                          |
| `nav`          | Header + tab nav labels                             |
| `common`       | Buttons, generic verbs (open, back, cancel, etc.)   |
| `home`         | Homepage hero, tiles, trust block                   |
| `calculadoras` | Calculator titles, summaries, group labels          |
| `recursos`     | Resource section titles                             |
| `software`     | Software section titles                             |
| `footer`       | Footer copy                                         |

Keep namespaces **flat where possible**. Nested keys like
`home.tiles.calculadoras.title` are fine; deeper than 3 levels is a smell.

## Server vs. client components

- **Server components** can call:
  - `await getTranslations('namespace')` — preferred for async pages
  - `useTranslations('namespace')` — works inside server components
    when `setRequestLocale(locale)` is called first
- **Client components** call `useTranslations('namespace')` directly;
  the provider is set up in `app/[locale]/layout.tsx`

## Adding a new string

1. Add the key to both `es.json` and `en.json` (mirror!)
2. In code: `const t = useTranslations('namespace'); t('key')`
3. For arrays (like trust list items): `t.raw('key') as string[]`

## Currency, dates, numbers

Use `Intl.NumberFormat` / `Intl.DateTimeFormat` with the active locale.
Helpers in `web/lib/utils.ts`:

```ts
formatCurrency(value, locale = 'es-US', options = {})
formatNumber(value, locale = 'es-US')
formatDate(date, locale = 'es-US')
```

**USD throughout** — currency is always USD; the *formatting* changes
with locale (`$1.500` vs `$1,500`).

## Language toggle

`web/components/language-toggle.tsx`:

- Reads current locale via `useLocale()`
- On click, calls `router.replace(pathname, { locale: 'en' | 'es' })`
- Preserves the current route — switching from `/es/herramientas/calculadoras/mortgage`
  takes you to `/en/herramientas/calculadoras/mortgage`
- Visually a small caps `ES / EN` toggle in the header

## Routes are NOT translated

**Decision:** Route segments stay Spanish (`/herramientas/calculadoras`)
even on the English locale. This keeps URLs canonical and simplifies
maintenance.

The English visitor experiences:

- URL: `/en/herramientas/calculadoras/fix-flip`
- UI: all labels in English
- Code/data: same files, just different message keys

## Translation discipline

- Don't machine-translate at runtime — author both strings deliberately
- For contracts: **do NOT translate UI strings around an English legal
  body**. There are two separate full-language contract templates. See
  [[05 — Contratos]].
- Spanish dictionary terms preserve regional voicing where it matters
  (e.g. "Wholesaling (mayoreo)") — both the Anglicism and the Spanish
  word in the term itself, because that's how operators actually speak.
